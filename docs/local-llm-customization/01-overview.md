# 第1章 全体像

## この章で学ぶこと

この章では、軽量ローカルLLMをカスタマイズする方法を大きく分類し、それぞれが何を変える方法なのかを整理します。

ローカルLLMを研究・教育で使うとき、重要なのは「どのモデルが一番賢いか」だけではありません。むしろ、何をプロンプトで制御し、何を資料検索で補い、何をツールに任せ、どこから学習が必要になるのかを見分けることが大切です。

## カスタマイズの5分類

軽量ローカルLLMのカスタマイズは、次の5つに分けると理解しやすくなります。

| 方法 | 変える対象 | 得意なこと | 研究・教育での例 |
| --- | --- | --- | --- |
| プロンプト設計 | 指示 | 役割、文体、回答形式 | 研究相談、講評、授業説明 |
| RAG | 参照資料 | 手元資料に基づく回答 | 授業資料QA、論文検索、研究室FAQ |
| ツール連携 | 外部機能 | 計算、検索、ファイル処理 | CSV分析、BibTeX整理、LaTeX確認 |
| LoRA / QLoRA | 一部の重み | 出力形式や判断基準の安定化 | 講評文、分類、定型要約 |
| 継続事前学習 | 言語感覚 | 専門分野の文体や語彙への適応 | 分野論文、専門用語、技術文書 |

## まず大事な区別

カスタマイズには、モデルの重みを変えない方法と、重みを変える方法があります。

```mermaid
flowchart TD
  A["ローカルLLMのカスタマイズ"] --> B["重みを変えない"]
  A --> C["重みを変える"]

  B --> D["プロンプト設計"]
  B --> E["RAG"]
  B --> F["ツール連携"]

  C --> G["LoRA / QLoRA"]
  C --> H["継続事前学習"]
```

最初は、重みを変えない方法から始めるのがよいです。理由は単純で、すぐ試せて、失敗しても戻しやすいからです。

特に助教業務では、授業資料、論文、研究メモ、学生向けFAQなど、更新される資料が多くあります。こうした情報はモデルに覚え込ませるより、RAGで検索して渡す方が管理しやすいです。

## 何をどの方法で扱うか

```mermaid
flowchart TD
  A["やりたいこと"] --> B{"手元資料に基づく？"}
  B -->|はい| C["RAG"]
  B -->|いいえ| D{"答え方を揃えたい？"}
  D -->|はい| E["プロンプト設計"]
  E --> F{"プロンプトだけで不安定？"}
  F -->|はい| G["LoRA / QLoRA"]
  F -->|いいえ| H["プロンプトで十分"]
  D -->|いいえ| I{"計算や検索が必要？"}
  I -->|はい| J["ツール連携"]
  I -->|いいえ| K{"専門分野の言語感覚が必要？"}
  K -->|はい| L["継続事前学習"]
  K -->|いいえ| M["通常のLLM利用"]
```

この図で大事なのは、LoRAや継続事前学習を早く選びすぎないことです。

たとえば「授業資料を覚えさせたい」と思った場合、多くはLoRAではなくRAGです。「講評文の文体をいつも同じにしたい」と思った場合は、まずプロンプト設計、それでも揺れるならLoRAです。

## 助教業務での代表的な構成

研究・教育支援として実用的なのは、次の組み合わせです。

```text
ローカルLLM
+ 研究・教育用システムプロンプト
+ 授業資料・論文・研究メモのRAG
+ Python・ファイル検索・CSV処理などのツール
```

この構成でできること:

- 授業資料に基づく質問応答
- 学部生向け説明への言い換え
- 論文群の比較整理
- 研究アイデアの壁打ち
- 実験データの概要確認
- レポート講評の下書き
- 研究室FAQの作成

次章から、それぞれの方法を詳しく見ていきます。
