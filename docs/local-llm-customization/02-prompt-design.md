# 第2章 プロンプト設計

## この章で学ぶこと

プロンプト設計は、モデルの重みを変えずに、役割、文体、回答形式、判断基準を指定する方法です。

ローカルLLMのカスタマイズでは、最初に試すべき方法です。特別な学習データもGPU学習も不要で、すぐに実験できます。

## プロンプト設計で変えられるもの

プロンプトで指定しやすいのは、次のような要素です。

- 役割
- 対象読者
- 出力形式
- 口調
- 判断基準
- 禁止事項
- 不確実な場合の振る舞い

研究・教育用途では、モデルに「大学助教を支援するアシスタント」として振る舞わせるだけでも、回答の方向性がかなり変わります。

## 基本テンプレート

```text
あなたは大学助教を支援する研究・教育アシスタントです。

基本方針:
- 不確かなことは断定しない
- 根拠がない場合は「要確認」と書く
- 研究相談では、仮説、根拠、検証方法、注意点に分ける
- 授業支援では、学部生にも伝わる説明を優先する
- 個人情報や成績に関わる内容は慎重に扱う

出力形式:
1. 要点
2. 詳細
3. 次に確認すること
```

このテンプレートは、研究相談、授業準備、メール文案、講評文の下書きなどに広く使えます。

## 授業支援のプロンプト

```text
以下の内容を、学部2年生向けに説明してください。
専門用語は使ってよいですが、初出時に短く補足してください。
最後に理解確認問題を3問作ってください。
```

使い道:

- 授業スライドの説明文作成
- 演習問題の導入文作成
- 難しい論文内容の初学者向け説明
- 学生からの質問への回答案作成

## 研究相談のプロンプト

```text
以下の研究アイデアについて、助教との研究相談としてコメントしてください。

観点:
- 仮説
- 期待される貢献
- 必要な先行研究
- 実験設計
- 失敗しやすい点
- 次にやるべき小さな検証
```

このプロンプトは、研究テーマの初期検討に向いています。重要なのは、モデルに結論だけを出させるのではなく、観点を分解させることです。

## レポート講評のプロンプト

```text
以下の学生レポートに講評を書いてください。

条件:
- 学生を否定する表現は避ける
- 良い点を先に述べる
- 改善点は具体的に書く
- 次に何をすればよいかを1つ以上示す
- 成績評価は出さない

出力形式:
良い点:
改善点:
次回意識するとよいこと:
```

講評では、モデルの出力が強すぎる表現になることがあります。そのため、文体と禁止事項を明示すると安全です。

## プロンプト設計の限界

プロンプト設計だけでは、モデルは手元の授業資料や研究室資料を知りません。

たとえば、次のような質問には限界があります。

```text
去年の第5回授業で説明した内容に基づいて、復習問題を作ってください。
```

この場合、モデルが去年の資料を知らなければ答えられません。無理に答えさせると、それらしいが根拠のない内容を作る危険があります。

こうした場合は、第3章のRAGを使います。
