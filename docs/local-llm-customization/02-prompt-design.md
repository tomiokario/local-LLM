# 第2章 プロンプト設計

## この章で学ぶこと

プロンプト設計は、モデルの重みを変えずに、役割、文体、回答形式、判断基準を指定する方法です。

ローカルLLMのカスタマイズでは、最初に試すべき方法です。特別な学習データもGPU学習も不要で、すぐに実験できます。

## プロンプト設計で変えられるもの

プロンプトで指定しやすいのは、次のような要素です。

- 役割
- 対象読者
- 出力形式
- 口調
- 判断基準
- 禁止事項
- 不確実な場合の振る舞い

文書作成やコーディングでは、モデルに「作業を支援するアシスタント」として振る舞わせるだけでも、回答の方向性がかなり変わります。

## 基本テンプレート

```text
あなたは文書作成、コーディング、確認作業を支援するアシスタントです。

基本方針:
- 不確かなことは断定しない
- 根拠がない場合は「要確認」と書く
- アイデア相談では、仮説、根拠、検証方法、注意点に分ける
- 説明文では、初めて読む人にも伝わる説明を優先する
- 公開可否が曖昧な入力は扱わない

出力形式:
1. 要点
2. 詳細
3. 次に確認すること
```

このテンプレートは、作業相談、説明文、メール文案、コメント文の下書きなどに広く使えます。

## 説明文作成のプロンプト

```text
以下の内容を、初めて読む人向けに説明してください。
専門用語は使ってよいですが、初出時に短く補足してください。
最後に理解確認問題を3問作ってください。
```

使い道:

- 資料の説明文作成
- 手順書の導入文作成
- 難しい技術内容の初学者向け説明
- 読者からの質問への回答案作成

## アイデア整理のプロンプト

```text
以下の作業アイデアについて、検討コメントを作ってください。

観点:
- 仮説
- 期待される効果
- 必要な前提確認
- 検証方法
- 失敗しやすい点
- 次にやるべき小さな検証
```

このプロンプトは、作業案の初期検討に向いています。重要なのは、モデルに結論だけを出させるのではなく、観点を分解させることです。

## コメント作成のプロンプト

```text
以下の文書にコメントを書いてください。

条件:
- 書き手を否定する表現は避ける
- 良い点を先に述べる
- 改善点は具体的に書く
- 次に何をすればよいかを1つ以上示す
- 評価値は出さない

出力形式:
良い点:
改善点:
次回意識するとよいこと:
```

コメント作成では、モデルの出力が強すぎる表現になることがあります。そのため、文体と禁止事項を明示すると安全です。

## プロンプト設計の限界

プロンプト設計だけでは、モデルは手元の手順書や作業メモを知りません。

たとえば、次のような質問には限界があります。

```text
前回の手順書で説明した内容に基づいて、確認問題を作ってください。
```

この場合、モデルが該当資料を知らなければ答えられません。無理に答えさせると、それらしいが根拠のない内容を作る危険があります。

こうした場合は、第3章のRAGを使います。
