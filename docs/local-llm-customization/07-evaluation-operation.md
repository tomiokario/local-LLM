# 第7章 評価と運用

## この章で学ぶこと

ローカルLLMのカスタマイズでは、作ること以上に、評価して運用することが重要です。

特に研究・教育では、誤回答、根拠不明、個人情報、未公開研究データの扱いに注意が必要です。

## 評価が必要な理由

LLMは、流暢に間違えることがあります。

授業や研究で使う場合、次のような問題が起こりえます。

- 授業資料にない内容を断定する
- 論文の主張を取り違える
- 学生レポートに強すぎる講評を書く
- 統計結果を誤って説明する
- 出典を曖昧にする
- 未公開情報をログに残す

そのため、カスタマイズしたら必ず小さな評価セットを作ります。

## 最低限の評価セット

最初は小さくてよいので、用途ごとに評価質問を用意します。

```text
eval/
  research_questions.md
  lecture_questions.md
  grading_comments.md
  rag_grounding_checks.md
```

評価観点:

- 回答が根拠資料に基づいているか
- 出典を示せるか
- 不明なことを不明と言えるか
- 学生向け説明がわかりやすいか
- 講評が過度に断定的でないか
- 個人情報を不要に含めていないか

## RAGの評価

RAGでは、回答の良し悪しだけでなく、検索が正しいかを見ます。

確認すること:

- 関係する資料が検索されているか
- 関係ない資料が混ざりすぎていないか
- 出典が表示されているか
- 資料にないことを推測していないか
- 古い資料と新しい資料が混ざる場合に区別できるか

RAGの失敗は、モデルの回答だけを見ても原因がわからないことがあります。検索結果そのものを確認できるようにしておくと改善しやすいです。

## LoRAの評価

LoRAでは、形式や文体が安定したかを見ます。

確認すること:

- 出力形式を守るか
- 文体が揃っているか
- 不自然に同じ表現を繰り返さないか
- 余計な断定が増えていないか
- 本来できていた一般的な応答が劣化していないか

特定タスクだけでよく見えても、別の入力で崩れることがあります。評価例は少し幅を持たせるとよいです。

## 個人情報と未公開情報

ローカルLLMはクラウドに比べて扱いやすい面がありますが、完全に安全という意味ではありません。

確認すること:

- チャットログが保存される場所
- RAG用データベースの保存場所
- 学生名や成績情報を入れる必要があるか
- 共有PCや研究室PCで誰がアクセスできるか
- 外部APIを使っていないか

成績、学生相談、未公開研究データは、最初は匿名化して扱うのが安全です。

## 運用の基本方針

研究・教育で使う場合、次の方針が現実的です。

- 最終判断は人間が行う
- 根拠が必要な回答では出典を表示する
- 学生情報は原則匿名化する
- 重要なメールや講評は必ず人間が読む
- RAG資料の更新履歴を残す
- モデルやプロンプトを変えたら評価質問で確認する

LLMは、判断を置き換えるものではなく、下書き、探索、整理、確認を助ける道具として使うのが安全です。
