# 第6章 追加学習の判断と実践

## この章で学ぶこと

この章では、ローカル LLM を活用した後に追加学習が必要かを判断し、Notebook では短い教材コーパスを使って continued-pretraining 風の追加学習を実際に実行します。

学習は目的ではなく手段です。まず Chat UI、Ollama API、RAG、エージェンティック coding、文書やコードのレビューで使い、そこで残る不足から逆算します。実験ではベースモデル全体を更新せず、LoRA adapter による短い追加学習として扱い、学習成果物は repository に混ぜません。

## 先に試すこと

追加学習を考える前に、次を試します。

- Chat UI で短い相談や文章化を試す
- Notebook から Ollama API を呼び、同じ質問で比較する
- RAG で資料に基づく回答にする
- coding agent に小さな調査や修正を任せる
- 変更差分をレビューさせる
- 評価セットで、同じ失敗が繰り返されるかを見る

多くの場合、プロンプト、RAG、確認観点の整理だけで改善できます。

## 何が足りないかで選ぶ

| 症状 | 先に試すこと | それでも足りない場合 |
| --- | --- | --- |
| 資料に基づかない | RAG の検索、チャンク、出典表示を見直す | RAG の改善を続ける |
| 出力形式が揺れる | プロンプトで形式を固定する | LoRA / QLoRA |
| 確認観点を毎回落とす | 観点リストをプロンプトに入れる | LoRA / QLoRA |
| 分野の語彙や文体が弱い | 用語集や例を RAG で渡す | 継続事前学習を検討 |
| coding agent が作法を外す | AGENTS.md、README、既存差分を明示する | LoRA / QLoRA または継続事前学習を検討 |

## 評価セットを先に作る

追加学習を始める前に、改善したい用途を評価できる質問を用意します。

例:

```text
ローカル LLM の使い始めに必要な確認を、結論から3点で説明してください。
```

```text
README と Notebook 目次の差分を、初心者導線の観点でレビューしてください。
```

```text
変更前に git status を確認し、対象ファイルだけを編集する作業計画を作ってください。
```

評価セットがないと、学習後に良くなったのか、単に雰囲気が変わったのか判断できません。

## 継続事前学習を検討してよい条件

継続事前学習は、次の条件がそろってから検討します。

- 実際の活用記録がある
- 失敗例が複数あり、原因がプロンプト不足や RAG 不足だけではない
- 評価セットで改善前後を比べられる
- 入力範囲と保存先を整理できている
- 学習成果物を教材 repository に混ぜない運用が決まっている
- 悪化した時に戻せる方法がある

## 実行計画の考え方

追加学習をする場合は、次を先に決めます。

- 目的: 何を改善したいのか
- baseline: 現在のモデルでどこまでできるのか
- method order: プロンプト、RAG、LoRA / QLoRA、継続事前学習の順に試す
- output location: 学習成果物をどこへ置くのか
- success metric: 何を満たせば成功とするのか
- rollback: 悪化した時に戻す方法

ローカル LLM 活用では、学習を急ぐより、使い方と評価を先に固める方が失敗しにくくなります。
