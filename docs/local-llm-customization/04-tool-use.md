# 第4章 ローカル LLM の活用ワークフロー

## この章で学ぶこと

この章では、ローカル LLM を実際の作業でどう使うかを扱います。

ツール呼び出しの内部構造を作ることが目的ではありません。Chat UI を開いて相談する、Notebook から Ollama API を呼ぶ、Cline や aider でエージェンティック coding をする、文書やコードをレビューさせる、といった入口を使い分けられるようにします。

## 4つの入口

| 入口 | 向いていること | 最初の一手 |
| --- | --- | --- |
| Chat UI | 相談、要約、文章化、比較 | 短い依頼を投げて、出力の癖を見る |
| Ollama API | Notebook 実験、定型プロンプト比較 | 同じ質問をモデルや温度を変えて試す |
| エージェンティック coding | 調査、編集、テスト、PR 説明 | 小さな差分だけ任せ、必ず diff を確認する |
| 文書やコードのレビュー | README、Notebook、コード差分の点検 | 観点を指定して、重大度順に指摘させる |

## Chat UI で試す

Chat UI は、ローカル LLM をいちばん気軽に使う入口です。

最初は次のような依頼が向いています。

```text
ローカル LLM を文書作成、コーディング、資料確認で使う時、最初の1週間で試す小さな用途を5つ提案してください。
```

```text
次の文章を、前提・結論・次に確認することの3つに分けて要約してください。
```

Chat UI では、考えを整理する、別案を出す、文章の下書きを作る、といった作業から始めます。ファイル編集やコマンド実行はまだ任せません。

## Ollama API で試す

Notebook から Ollama API を呼ぶと、同じプロンプトを何度も比較できます。

向いていること:

- プロンプトの比較
- モデルの比較
- RAG と通常回答の比較
- 確認観点の固定
- 同じ評価質問での回帰確認

Chat UI で良さそうな依頼が見つかったら、Notebook に移して再現できる形にします。

## エージェンティック coding で試す

Cline や aider のような coding agent は、ローカル LLM を repository 作業に接続する入口です。

最初に頼むなら、編集より調査が安全です。

```text
この repository の README と notebooks の導線を調べ、初心者が迷いそうな箇所を3つ挙げてください。まだ編集しないでください。
```

編集を頼む場合も、対象を小さくします。

```text
README の Notebook 目次にリンク切れがないか確認し、必要な場合だけ最小差分で修正してください。変更後に git diff を説明してください。
```

coding agent は便利ですが、最終判断を任せるものではありません。差分、検証結果、対象ファイルを人間が確認します。

## 文書やコードのレビューで試す

文書やコードのレビューでは、LLM に漠然と「見て」と頼むより、観点を渡します。

```text
次の差分を、初心者向け教材としての分かりやすさ、リンク導線、実行時のつまずき、公開可否を確認済みの教材用サンプルだけを扱っているか、という観点でレビューしてください。
重大な指摘から順に挙げてください。
```

確認用途では、モデルの得意不得意も出ます。文章の自然さは Gemma 系、構造化された観点整理やコード周辺は Qwen 系、といったように比較すると判断しやすくなります。

## 進め方

迷ったら、次の順に試します。

1. Chat UI で短い相談をする
2. 同じプロンプトを Notebook から Ollama API で呼ぶ
3. RAG を足して、資料に基づく回答にする
4. coding agent に小さな調査や修正を依頼する
5. 変更差分をレビューさせる
6. それでも同じ型が崩れるなら LoRA / QLoRA を検討する

ローカル LLM の活用では、モデルそのものを作るより先に、使う画面、渡す文脈、確認する手順を整えることが大切です。
